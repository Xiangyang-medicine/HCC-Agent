## Executive Summary

This audit reveals **critical methodological flaws** across the codebase that invalidate the reported results. The main issues are:
1. The "LLM Agent" is NOT actually using an LLM - it's a hardcoded rule-based scoring system
2. External validation datasets use pre-existing signatures, not the team's method
3. Statistical metric implementations are fundamentally incorrect
4. Weights were optimized on validation sets (data leakage)
5. Mock/synthetic data is used without proper labeling

**Recommendation**: All current quantitative results must be marked as `legacy_unvalidated`. A complete rework following established survival analysis methodology is required.

## 3. Critical Methodological Issues

### 3.1 ISSUE #1: "LLM Agent" is NOT an LLM Agent

**Severity**: CRITICAL - Misrepresentation of methodology

**Evidence**:

**File**: `src/evaluation/llm_agent_evaluation.py`

Lines 283-346 (`_calculate_hybrid_score`):
```python
def _calculate_hybrid_score(self, patient: PatientData) -> float:
    # Stage hazard weights (higher = more hazardous)
    STAGE_HAZARD = {
        'Stage I': 0.08, 'Stage II': 0.18, 'Stage IIIA': 0.30,
        'Stage IIIB': 0.42, 'Stage IV': 0.55
    }

    # Gene hazard contributions - INCREASED weights for better discrimination
    GENE_HAZARD = {
        "HK2": 0.20, "PKM": 0.15, "LDHA": 0.25, "GLS": 0.22,
        "CA9": 0.28, "VEGFA": 0.18, "HIF1A": 0.18, "MYC": 0.22,
        "FASN": 0.15, "SCD": 0.14, "GPI": 0.12, "PFKL": 0.10,
        "LDHB": -0.12, "GLUD1": -0.10
    }

    # Total hazard
    total_hazard = base_hazard + stage_hazard + gene_hazard + afp_hazard + grade_hazard
    risk_score = total_hazard
```

Lines 511-588 (`_evaluate_mock`):
```python
def _evaluate_mock(self, patient: PatientData) -> AgentEvaluationResult:
    # Stage hazard weights
    STAGE_HAZARD = {...}
    # Gene hazard contributions - INCREASED weights for better discrimination
    GENE_HAZARD = {...}
    # Total hazard
    total_hazard = base_hazard + stage_hazard + gene_hazard + afp_hazard + grade_hazard
    risk_score = np.clip(total_hazard, 0.05, 0.95)
```

**File**: `GSE116174/generate_figures_v2.py`

Lines 112-124:
```python
# LLM Agent: Weighted ensemble of metabolic pathways + clinical
# Optimized weights for superior performance (C-index=0.76, HR=5.98, p<0.001)
llm_risk = (
    0.10 * warburg_score +
    0.10 * hypoxia_score +
    0.10 * glutamine_score +
    0.15 * lipogenesis_score +
    0.05 * oncogenic_score +
```

**Problem**: The "LLM Agent" is purely a mathematical formula with hardcoded weights. No LLM is used for risk prediction. The `_evaluate_with_real_llm` method (lines 233-281) only calls LLM for "qualitative analysis" - the quantitative risk score comes entirely from `_calculate_hybrid_score`.

**Impact**: All claims about "LLM Agent performance" are actually claims about a rule-based scoring system.

### 3.4 ISSUE #4: Incorrect Survival Analysis Metrics

**Severity**: HIGH - Invalid statistical inference

**Evidence**:

**File**: `src/evaluation/prognosis_evaluator.py`

**C-index (lines 158-215)**:
```python
# Custom C-index implementation - does NOT match Harrell's or Uno's C-index
# Problem 1: No proper handling of ties
# Problem 2: No censoring adjustment
# Problem 3: No variance estimation
```

**Time-dependent AUC (lines 241-292)**:
```python
# Uses simple Mann-Whitney without IPCW weighting
# IPCW (Inverse Probability of Censoring Weighting) is required for proper
# time-dependent AUC in survival analysis
```

**Brier Score (lines 338-369)**:
```python
# Lines 363-367: INCORRECT IMPLEMENTATION
threshold = 0.5
binary_pred = (preds_normalized > threshold).astype(float)
# Simple Brier score
brier = np.mean((binary_pred - events) ** 2)
```

The Brier score for survival analysis requires:
1. IPCW weighting for censoring
2. Prediction of survival probability at time t, not binary classification
3. Integration over time (Integrated Brier Score)

**Impact**: All C-index, AUC, and Brier Score values are unreliable.

## 6. Recommended Fix Order

### Phase A: Immediate Corrections (Before Any Publication)

1. **Remove all "LLM Agent" claims** from results where only rule-based scoring was used
2. **Mark all current figures as `legacy_unvalidated`**
3. **Correct the statistical metrics** - use established libraries (lifelines, scikit-survival, pycox)
4. **Document** which results use real data vs mock

### Phase B: Methodological Corrections

1. **Implement proper survival analysis metrics**:
   - Use `lifelines.utils.concordance_index` (Harrell's C-index)
   - Use `lifelines.utils.calibration_survival_curve` for calibration
   - Use `sksurv.metrics.concordance_index_censored` for IPCW C-index
   - Use `pycox.evaluation.Evaluator` for proper time-dependent AUC and Brier Score

2. **If claiming LLM Agent evaluation**:
   - Actually integrate a real LLM API call
   - Use LLM output directly, not as a post-hoc modifier
   - Compare against baselines WITHOUT using the same formula

3. **External validation**:
   - Implement actual cross-platform transfer learning
   - Or clearly state using pre-existing validated signatures

### Phase C: Validation

1. **Split data properly**: Train on one cohort, validate on completely independent cohort
2. **Report confidence intervals** from proper bootstrapping
3. **Conduct ablation studies** to demonstrate LLM contribution
4. **Validate on real clinical endpoints** if claiming clinical utility
